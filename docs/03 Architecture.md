# Architecture

> 状态：Draft
> 来源：生态调研与用户调研材料。

## 架构目标

AI Director OS 是一个统一、完整、可操作的小说转短剧工作台，而不是将小说在多个独立软件之间导入导出。它由工作台、导演与记忆、生成调度、质量控制和输出组成；每一层产出结构化中间资产，使任意阶段可以独立审阅、修改和重跑。

    ├── Image Router

    ├── Voice Router
    ├── 任务队列
    ├── 重试与回退

## 层间职责

### 前端工作台

面向创作者与制作人员，承担项目管理、资产审阅、逐镜头决策和时间线交付。用户始终在同一个产品中完成主流程，不需要接触或操作后台生成引擎。

### 导演与记忆层

将小说转换为可生产的季、集、场、镜头，并维护角色和剧情的跨镜头状态。该层是系统的创作决策中心，不能被 Prompt 或 Provider 状态取代。

### 生成调度层

根据镜头要求选择图像、视频和语音 Provider，管理异步队列、依赖关系、失败回退、重试与预算。它对上消费镜头规格和资产状态，对下执行具体 Provider 工作流。

### 质量层

针对已生成资产进行人物、构图、连续性、技术质量、字幕和口型检查；其结果必须能定位到具体镜头和问题类型，以便只重做受影响的资产。

### 输出层

将审核通过的镜头、音频和字幕编排为可发布成片。输出层不应反向成为唯一事实来源，时间线及其组成资产仍须可追溯到 Story State 和生成任务。

## 架构原则

- 产品必须以一个主系统承载完整工作台和项目管理。Toonflow、ViMax、Wind Comic 等只可作为主系统候选底座或设计参考，不能成为用户需要串行操作的多个产品。
- 每层输出必须为结构化、可复用的中间资产，支持非破坏性修改和单阶段重跑。
- Provider 只能通过 Router 接入；业务层不得依赖某个模型的特定 Prompt 或返回格式。
- 连续镜头的状态依赖应显式建模，不能通过提升全局并发来掩盖。
